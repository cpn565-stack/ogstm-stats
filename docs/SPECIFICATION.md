## 1. 專案概述

### 1.1 背景

課程中使用「思考圖」進行小組討論與表決。每組在紙本思考圖上，針對各選項以**綠勾（贊成）**與**紅勾（反對）**標記票數。助教需在課堂中快速彙整各組結果，講師需即時掌握統計並向全班呈現，課後需保留歷史資料供分析。

### 1.2 目標

建立一套 Web 系統，達成：

1. **快速輸入**：助教以拍照或手動方式登錄各組票數
2. **即時呈現**：講師在課堂中查看各題**前五名**熱門選項
3. **資料留存**：各場次、各小組的選項資料永久保留
4. **歷史分析**：支援跨場次查詢與匯出
5. **公開洞察**：於 `stats.ogstm.com` 呈現組織最常見的表決趨勢（去識別化加總）

### 1.3 非目標（Out of Scope — V1）

- 個別學員層級的追蹤（V1 以**小組**為單位）
- 串接 LLM / 外部 AI API 作為主要辨識手段
- 學員自行輸入（僅助教操作）
- 即時協作編輯（多位助教同時編輯同一格）

## 2. 使用者角色

| 角色 | 主要操作 | 裝置 |
|------|----------|------|
| **助教（TA）** | 建立課程、輸入各組票數、修正辨識結果 | 手機為主 |
| **講師（Instructor）** | 課堂投影：各題前五名、即時統計 | 電腦／投影機 |
| **公開訪客** | 瀏覽跨場次歷史趨勢（常見狀況） | 任意 |
| **管理者（Admin）** | 後台：場次明細、各組原始資料、匯出 | 電腦（**僅團隊**） |

**權限原則**：

- 公開區：僅顯示**跨場次加總**與排行，不暴露單場次各組明細
- 營運區（`/session/*`）：助教課堂操作，網址不對外宣傳
- 後台（`/admin/*`）：**必須登入**（實作時列為 P0，上線前完成）

## 3. 思考圖模板（輸入假設）

### 3.1 題型（已確認：2 題、版型不同）

共 **2 題表決**，每題各 1 個固定版本，**紙本版型不同**，但統計邏輯相同：

- 每題有多個選項（代號 a, b, c…）
- 每個選項有**綠色框**（贊成）與**紅色框**（反對）
- 統計各框內的勾選／標記**數量**（人次）

```
題型 A（表決 1）          題型 B（表決 2）
┌──────────────┐          ┌──────────────┐
│ 版型 A        │          │ 版型 B        │  ← 版面配置不同
│ 選項 a [綠][紅]│          │ 選項 a [綠][紅]│
│ 選項 b [綠][紅]│          │ 選項 b [綠][紅]│
│ …            │          │ …            │
└──────────────┘          └──────────────┘
         ↓                         ↓
    各自獨立 ROI 標定         各自獨立 ROI 標定
```

模板設定上，兩題以獨立 `question` 條目管理，各自擁有：

- 不同的 `options` 清單（選項數量可不同）
- 不同的 `rois` 座標（因紙本版型不同）

### 3.2 統計範圍

| 欄位 | 是否統計 | 說明 |
|------|----------|------|
| 組別 | ✅（識別用） | 區分各小組 |
| 條件／選項清單、討論、結論 | ❌ | 紙本參考／文字區 |
| 表決 1（題型 A） | ✅ | 各選項綠框／紅框標記數量 |
| 表決 2（題型 B） | ✅ | 各選項綠框／紅框標記數量 |

### 3.3 前五名排行規則（講師視圖）

每題獨立計算，排序規則：

1. **主排序**：贊成票數（綠）由高到低
2. **次排序**：反對票數（紅）由低到高
3. **取前 5 名**；不足 5 個選項時全部顯示
4. 並列時依選項代號字母順序

講師視圖以「前五名贊成選項」為主視覺；另可折疊查看反對排行或完整列表。

## 5. 辨識技術規格

### 5.1 是否需要 AI / LLM？

**核心流程不需要。** P0 功能（手動輸入、統計、講師視圖、後台）皆不依賴 LLM。

**選配方案（V1.5）**：可串接 **Gemini 3.1 Flash-Lite 免費版** 作為拍照辨識備援與文字摘要生成，詳見 **附錄 D**。

| 方案 | 技術 | 是否需要外部 API | 定位 |
|------|------|------------------|------|
| 手動輸入 | 表單 | 否 | **主要保底（P0）** |
| 拍照辨識（本地） | 瀏覽器 Canvas + HSV 色彩分析 | 否 | **首選自動化（P1）** |
| 拍照辨識（LLM） | Gemini 3.1 Flash-Lite Vision | 是（免費額度） | **備援（V1.5）** |
| 文字摘要 | Gemini 3.1 Flash-Lite 文字 | 是（免費額度） | **公開頁文案（V1.5）** |

### 5.2 拍照辨識流程

```
┌──────────┐    ┌──────────────┐    ┌─────────────┐    ┌──────────┐
│ 拍照上傳  │ →  │ 載入至 Canvas │ →  │ ROI 區域裁切 │ →  │ HSV 色彩  │
└──────────┘    └──────────────┘    └─────────────┘    │ 比例分析  │
                                                         └─────┬────┘
                                                               ↓
┌──────────┐    ┌──────────────┐    ┌─────────────┐    ┌──────────┐
│ 存入後台  │ ←  │ 助教確認修正  │ ←  │ 信心分數評估 │ ←  │ 票數推算  │
└──────────┘    └──────────────┘    └─────────────┘    └──────────┘
```

### 5.3 色彩判斷參數（初始值，可調）

| 顏色 | HSV 條件 |
|------|----------|
| 綠色（贊成） | 飽和度 > 0.2、亮度 > 0.2、色相 70°–170° |
| 紅色（反對） | 飽和度 > 0.2、亮度 > 0.2、色相 ≤ 20° 或 ≥ 330° |

### 5.4 票數推算（依顏色像素覆蓋比例）

| 覆蓋比例 | 推算人數 |
|----------|----------|
| < 4% | 0 |
| 4%–12% | 1 |
| 12%–22% | 2 |
| ≥ 22% | 3（或依每組人數上限調整） |

### 5.5 信心分數

- 每個勾選框計算綠／紅像素比例差異
- 差異大或兩者皆低 → 視為較有信心
- 輸出 0–1 分數；低於 0.7 時 UI 提示人工確認
- ROI 未標定時信心為 0，退回純手動

### 5.6 ROI 模板標定

**前置條件**：2026-06-24 取得兩種題型的空白思考圖。

因兩題版型不同，需**分別標定** ROI，於 `template.json` 設定：

```json
{
  "questions": [
    { "id": "vote_1", "label": "題型 A（表決 1）", "options": ["a","b","c"] },
    { "id": "vote_2", "label": "題型 B（表決 2）", "options": ["a","b","c","d"] }
  ],
  "rois": {
    "vote_1": {
      "a": { "green": [0.12, 0.55, 0.04, 0.03], "red": [0.17, 0.55, 0.04, 0.03] }
    },
    "vote_2": {
      "a": { "green": [0.10, 0.30, 0.05, 0.04], "red": [0.16, 0.30, 0.05, 0.04] }
    }
  }
}
```

座標格式：`[x, y, width, height]`，皆為相對於該題思考圖圖片的比例（0–1）。兩題若拍在同一張紙上，ROI 仍相對於整張圖；若分開拍照，V2 可支援分題上傳。

### 5.7 拍照辨識限制與因應

| 問題 | 因應 |
|------|------|
| 光線不均 | 提示拍攝角度；人工修正 |
| 塗改、手寫 | 手動修正；V2 可考慮透視校正 |
| 角度傾斜 | V2 加入透視變換；V1 要求大致對準 |
| 辨識錯誤 | 一律可人工覆寫，不阻擋儲存 |

## 6. 資料模型

### 6.1 Session（課程場次）

```typescript
interface Session {
  id: string;           // UUID
  name: string;         // 課程名稱
  templateId: string;   // 使用的模板 ID
  createdAt: string;    // ISO 8601
  updatedAt: string;
}
```

### 6.2 Submission（小組提交）

```typescript
interface Submission {
  id: string;
  sessionId: string;
  groupId: string;      // 組別，如 "3"
  votes: {
    [questionId: string]: {
      [option: string]: { green: number; red: number }
    }
  };
  source: "manual" | "photo";
  confidence?: number;    // 0–1，僅 photo 來源
  photoPath?: string;     // V2：可選儲存原圖
  createdAt: string;
  updatedAt: string;
}
```

### 6.3 Template（思考圖模板）

```typescript
interface ThinkingMapTemplate {
  id: string;
  name: string;
  questions: {
    id: string;         // 如 "vote_1"
    label: string;      // 如 "表決 1"
    options: string[];  // 如 ["a","b","c"]
  }[];
  rois?: {
    [questionId: string]: {
      [option: string]: {
        green: [number, number, number, number];
        red:   [number, number, number, number];
      }
    }
  };
}
```

### 6.4 儲存方式（V1）

- 檔案：`data/store.json`
- 結構：`{ sessions: Session[], submissions: Submission[] }`
- 寫入時機：每次提交／更新即寫入
- **部署必要條件**：`data/` 目錄可寫入且定期備份

### 6.5 儲存升級路徑（V2 建議）

當場次增多或需多人管理時，可遷移至 SQLite 或 PostgreSQL，API 介面不變。

### D. LLM 選配方案（Gemini 3.1 Flash-Lite）

> **定位**：V1.5 選配模組。核心流程（P0）不依賴 LLM；LLM 用於加速拍照辨識與文案生成，手動輸入永遠可用。

#### D.1 評估結論

| 問題 | 決策 |
|------|------|
| 是否串接？ | **是**，作為備援與摘要工具，非必要元件 |
| 優先模型 | `gemini-3.1-flash-lite`（[官方定價](https://ai.google.dev/gemini-api/docs/pricing)） |
| 優先方案 | 免費版；企業客戶課程再評估 Paid |
| 架構 | **HSV 本地優先 → 信心低時 Gemini → 助教確認 → 儲存** |

#### D.2 模型與免費額度

| 項目 | 說明 |
|------|------|
| 模型 ID | `gemini-3.1-flash-lite` |
| 輸入支援 | 文字、圖片、影片 |
| 免費版費用 | Input / Output tokens 免費 |
| 速率限制 | 依 AI Studio 專案 tier（[Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)） |
| 課堂用量估算 | 1 場 12 組 ≈ 12 次呼叫；每月 10 場 ≈ 120 次，預期在免費額度內 |
| 隱私注意 | **免費版內容可能用於改善 Google 產品**；企業課程建議 Paid 或僅送裁切後表決區 |

#### D.3 功能對照：是否需要 LLM

**不需要 LLM（維持現有做法）**

| 功能 | 做法 |
|------|------|
| 手動輸入 | 表單 |
| 跨組加總、前五名 | 程式計算 |
| 講師投影視圖 | 讀 DB + 輪詢更新 |
| 後台歷史、CSV 匯出 | 檔案／DB |
| 公開統計數字 | SQL／JSON 加總 |

**適合加 LLM**

| 功能 ID | 功能 | 優先級 | 說明 |
|---------|------|--------|------|
| LLM-01 | 整頁拍照 Vision 辨識 | P1 | 不需 ROI 標定；支援兩種不同版型 |
| LLM-02 | 塗改／手寫勾備援 | P1 | HSV 信心 < 0.7 時觸發 |
| LLM-03 | 組別 OCR | P2 | 自動讀取「組別：N」 |
| LLM-04 | 公開頁「常見狀況」敘述 | P2 | 餵統計數字生成可讀摘要 |
| LLM-05 | 課後洞察報告（後台） | P3 | 跨場次趨勢文字解讀 |
| LLM-06 | 異常標記 | P3 | 如「某格紅綠皆有標記」 |

**不建議用 LLM**

| 情境 | 原因 |
|------|------|
| 即時加總、前五名排序 | 程式更準、更快 |
| 辨識結果自動儲存 | 幻覺會污染歷史資料 |
| 講師視圖每 5 秒呼叫 API | 浪費額度且無必要 |
| 公開 API 直接送客戶原圖 | 隱私風險 |

```

    ↓

    ↓
```

#### D.5 Vision 辨識 API 規格（草案）

**端點**：`POST /api/recognize/gemini`

**Request**：
```json
{
  "sessionId": "uuid",
  "image": "base64 或 multipart",
  "templateId": "thinking_map_v1"
}
```

**Prompt 要點**：
- 附上題型 A、題型 B 的選項清單
- 說明綠框 = 贊成、紅框 = 反對
- 要求統計每格標記**數量**（人次）
- 使用 Structured Output / JSON Schema 強制格式

**Response**：
```json
{
  "group_id": "3",
  "confidence": 0.85,
  "votes": {
    "vote_1": {
      "a": { "green": 2, "red": 1 },
      "b": { "green": 0, "red": 3 }
    },
    "vote_2": {
      "a": { "green": 1, "red": 0 }
    }
  },
  "flags": ["vote_1.c 綠紅皆有標記，請人工確認"]
}
```

**行為規則**：
- `source` 儲存為 `photo`；額外記錄 `llmModel: "gemini-3.1-flash-lite"`
- `confidence` 來自 LLM 自評 + 伺服器驗證（選項數量是否在模板範圍內）
- **禁止**跳過助教確認直接寫入 DB

#### D.6 文字摘要 API 規格（草案）

**端點**：`POST /api/insights/generate`（僅後台或排程觸發）

**輸入**：跨場次加總 JSON（不含各組明細、不含原圖）

**輸出**：300 字內繁體中文摘要，描述「組織中最常見的表決狀況」

**快取**：結果寫入 `data/insights.json`，公開頁讀快取；資料更新後才重新生成

