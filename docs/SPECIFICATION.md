## 1. 專案概述

### 1.1 背景

課程中使用「思考圖」進行小組討論與表決。每組在紙本思考圖上，針對各選項以**綠勾（贊成）**與**紅勾（反對）**標記票數。助教需在課堂中快速彙整各組結果，講師需即時掌握統計並向全班呈現，課後需保留歷史資料供分析。

### 1.2 目標

建立一套 Web 系統，達成：

1. **快速輸入**：助教以拍照或手動方式登錄各組票數
2. **即時呈現**：講師在課堂中查看各題統計與熱門選項
3. **資料留存**：各場次、各小組的選項資料永久保留
4. **歷史分析**：支援跨場次查詢與匯出

### 1.3 非目標（Out of Scope — V1）

- 個別學員層級的追蹤（V1 以**小組**為單位）
- 串接 LLM / 外部 AI API 作為主要辨識手段
- 學員自行輸入（僅助教操作）
- 即時協作編輯（多位助教同時編輯同一格）

## 2. 使用者角色

| 角色 | 主要操作 | 裝置 |
|------|----------|------|
| **助教（TA）** | 建立課程、輸入各組票數、修正辨識結果 | 手機為主 |
| **講師（Instructor）** | 查看統計、課堂投影 | 電腦／投影機 |
| **管理者（Admin）** | 查詢歷史場次、跨場次統計、匯出資料 | 電腦 |

同一套系統透過不同頁面服務不同角色，V1 不強制身份驗證（可於 V2 加入）。

## 3. 思考圖模板（輸入假設）

### 3.1 題型

共 **2 題表決**（最終定稿後各 1 個版本）。示意結構如下：

```
┌─────────────────────────────────────┐
│ 組別：____                            │
│ 條件與選項（a, b, c…）— 不納入統計     │
│ 討論紀錄 — 不納入統計                  │
│ 表決 1：每選項 [贊成/綠] [反對/紅]     │
│ 表決 2：每選項 [贊成/綠] [反對/紅]     │
│ 結論 — 不納入統計                      │
└─────────────────────────────────────┘
```

### 3.2 統計範圍

| 欄位 | 是否統計 | 說明 |
|------|----------|------|
| 組別 | ✅（識別用） | 區分各小組 |
| 條件／選項清單 | ❌ | 紙本參考用 |
| 討論、結論 | ❌ | 自由文字 |
| 表決 1、表決 2 | ✅ | 每選項統計綠勾／紅勾**人數** |

### 3.3 待確認（實作前需定稿）

- [ ] 兩題各幾個選項（目前示意：題 1 為 a–f，題 2 為 a–e）
- [ ] 兩題版型是否相同
- [ ] 每組人數（影響拍照辨識上限判斷）
- [ ] 預期總組數（預設 12 組）
- [ ] 空白模板 PDF／高清 PNG（拍照辨識必要）

## 5. 辨識技術規格

### 5.1 是否需要 AI / LLM？

**不需要。** V1 不以 AI API 或 LLM 作為必要元件。

| 方案 | 技術 | 是否需要外部 API | V1 定位 |
|------|------|------------------|---------|
| 手動輸入 | 表單 | 否 | **主要保底** |
| 拍照辨識 | 瀏覽器 Canvas + HSV 色彩分析 | 否 | **首選自動化** |
| 輕量 CV 模型 | 本地或自架模型 | 可選 | V2 備援 |
| Vision LLM | GPT-4V 等 | 是（付費） | **不建議**，僅極端案例 |

### 5.2 拍照辨識流程

```
┌──────────┐    ┌──────────────┐    ┌─────────────┐    ┌──────────┐
│ 拍照上傳  │ →  │ 載入至 Canvas │ →  │ ROI 區域裁切 │ →  │ HSV 色彩  │
└──────────┘    └──────────────┘    └─────────────┘    │ 比例分析  │
                                                         └─────┬────┘
                                                               ↓
┌──────────┐    ┌──────────────┐    ┌─────────────┐    ┌──────────┐
│ 存入後台  │ ←  │ 助教確認修正  │ ←  │ 信心分數評估 │ ←  │ 票數推算  │
└──────────┘    └──────────────┘    └─────────────┘    └──────────┘
```

### 5.3 色彩判斷參數（初始值，可調）

| 顏色 | HSV 條件 |
|------|----------|
| 綠色（贊成） | 飽和度 > 0.2、亮度 > 0.2、色相 70°–170° |
| 紅色（反對） | 飽和度 > 0.2、亮度 > 0.2、色相 ≤ 20° 或 ≥ 330° |

### 5.4 票數推算（依顏色像素覆蓋比例）

| 覆蓋比例 | 推算人數 |
|----------|----------|
| < 4% | 0 |
| 4%–12% | 1 |
| 12%–22% | 2 |
| ≥ 22% | 3（或依每組人數上限調整） |

### 5.5 信心分數

- 每個勾選框計算綠／紅像素比例差異
- 差異大或兩者皆低 → 視為較有信心
- 輸出 0–1 分數；低於 0.7 時 UI 提示人工確認
- ROI 未標定時信心為 0，退回純手動

### 5.6 ROI 模板標定

空白思考圖定稿後，於 `template.json` 設定各勾選框的相對座標：

```json
{
  "rois": {
    "vote_1": {
      "a": {
        "green": [0.12, 0.55, 0.04, 0.03],
        "red":   [0.17, 0.55, 0.04, 0.03]
      }
    }
  }
}
```

座標格式：`[x, y, width, height]`，皆為相對於整張圖片的比例（0–1）。

### 5.7 拍照辨識限制與因應

| 問題 | 因應 |
|------|------|
| 光線不均 | 提示拍攝角度；人工修正 |
| 塗改、手寫 | 手動修正；V2 可考慮透視校正 |
| 角度傾斜 | V2 加入透視變換；V1 要求大致對準 |
| 辨識錯誤 | 一律可人工覆寫，不阻擋儲存 |

## 6. 資料模型

### 6.1 Session（課程場次）

```typescript
interface Session {
  id: string;           // UUID
  name: string;         // 課程名稱
  templateId: string;   // 使用的模板 ID
  createdAt: string;    // ISO 8601
  updatedAt: string;
}
```

### 6.2 Submission（小組提交）

```typescript
interface Submission {
  id: string;
  sessionId: string;
  groupId: string;      // 組別，如 "3"
  votes: {
    [questionId: string]: {
      [option: string]: { green: number; red: number }
    }
  };
  source: "manual" | "photo";
  confidence?: number;    // 0–1，僅 photo 來源
  photoPath?: string;     // V2：可選儲存原圖
  createdAt: string;
  updatedAt: string;
}
```

### 6.3 Template（思考圖模板）

```typescript
interface ThinkingMapTemplate {
  id: string;
  name: string;
  questions: {
    id: string;         // 如 "vote_1"
    label: string;      // 如 "表決 1"
    options: string[];  // 如 ["a","b","c"]
  }[];
  rois?: {
    [questionId: string]: {
      [option: string]: {
        green: [number, number, number, number];
        red:   [number, number, number, number];
      }
    }
  };
}
```

### 6.4 儲存方式（V1）

- 檔案：`data/store.json`
- 結構：`{ sessions: Session[], submissions: Submission[] }`
- 寫入時機：每次提交／更新即寫入
- **部署必要條件**：`data/` 目錄可寫入且定期備份

### 6.5 儲存升級路徑（V2 建議）

當場次增多或需多人管理時，可遷移至 SQLite 或 PostgreSQL，API 介面不變。

## 7. API 規格

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET | `/api/sessions` | 列出所有課程 |
| POST | `/api/sessions` | 建立課程 `{ name? }` |

| DELETE | `/api/sessions/:id/submissions/:groupId` | 刪除單組提交 |
| GET | `/api/history` | 後台歷史總覽（含跨場次加總） |
| GET | `/api/export/:id` | 匯出單場次 CSV |
| GET | `/api/export/all` | 匯出全部歷史 CSV |

## 9. 介面與體驗規範

### 9.1 設計原則

- **行動優先**：助教輸入以手機操作為主
- **大字體投影**：講師視圖字級明顯大於一般頁面
- **雙色語意**：綠色 = 贊成，紅色 = 反對，全站一致
- **少打字**：以 +/- 步進器取代數字鍵盤輸入
- **可覆寫**：任何自動辨識結果皆可人工修正

### 9.2 色彩系統

| 用途 | 色碼 |
|------|------|
| 背景 | `#020617` |
| 主文字 | `#F8FAFC` |
| 強調／CTA | `#22C55E` |
| 贊成 | Emerald 系列 |
| 反對 | Rose 系列 |

### 9.3 字體

- 內文：Fira Sans
- 數字／選項代號：Fira Code

## 10. 部署規格

### 10.1 部署選項（二擇一）

| | `stats.ogstm.com` | `ogstm.com/stats` |
|---|---|---|
| DNS | 需新增子網域 | 不需額外 DNS |
| 環境變數 | `BASE_PATH=` 留空 | `BASE_PATH=/stats` |
| 站點 URL | `SITE_URL=https://stats.ogstm.com` | `SITE_URL=https://ogstm.com` |

### 10.2 技術棧

| 層級 | 技術 |
|------|------|
| 前端 | Next.js 16、React 19、Tailwind CSS 4 |
| 後端 | Next.js API Routes（Node.js） |
| 儲存 | JSON 檔案（`data/store.json`） |
| 辨識 | 瀏覽器 Canvas（無後端影像處理） |
| 部署 | Node `standalone` 模式或 Docker |

### 10.3 環境變數

```env
NEXT_PUBLIC_SITE_URL=https://stats.ogstm.com
NEXT_PUBLIC_BASE_PATH=
PORT=3000
```

### 10.4 伺服器需求

- Node.js 20+
- 持久化磁碟（`data/` 目錄）
- HTTPS（建議 Nginx 反向代理）
- **定期備份** `data/store.json`

### 10.5 不建議的部署方式

- 無狀態 Serverless（如 Vercel 預設）— `data/store.json` 無法持久保留
- 若必須用 Serverless，V2 需改用外部資料庫

## 11. 非功能需求

| 項目 | 要求 |
|------|------|

| 瀏覽器 | 支援 iOS Safari、Android Chrome（拍照功能） |
| 無障礙 | 按鈕具 aria-label；對比度符合 WCAG AA |

| 伺服器資料遺失 | 歷史統計消失 | 定期備份 `data/`；V2 改用資料庫 |
| 教室 WiFi 不穩 | 儲存失敗 | 顯示明確錯誤；V2 離線快取 |
| 後台無登入 | 資料被外人查看 | V2 加驗證；部署時不公開連結 |
